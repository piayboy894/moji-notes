# 公开更新查询

2.3.0 / 2.4.0 的 Windows 更新只请求 `api.github.com`，每次获取最多 30 条完整 Release 数据；安卓获取最多 50 条。实测 Windows 响应约 700 KB。Windows 的连接、HTTP 错误和超时都曾被映射为相同的“请检查网络”，安卓部分错误则只显示“检查更新失败”。因此旧版截图不足以判定是用户网络、DNS、代理、TLS 还是 GitHub 接口限制。网页能打开也不代表 API 域名或下载域名能连接；低延迟同样不能证明这些连接成功。

2.4.1 的两端并行读取本平台的两份小型清单：

- `https://raw.githubusercontent.com/piayboy894/moji-notes/main/updates/windows.json`（手机为 `android.json`）。
- `https://github.com/piayboy894/moji-notes/releases/download/update-channel/windows.json`（手机同理）。

清单仅数百字节，包含最新已发布稳定版的版本、官方文件地址、体积和 SHA-256。读取不需要账号、Token 或私人数据仓库；两份有效清单按版本号取最大值，避免渠道缓存不一致时退到更旧的版本。一条路径失败可以使用另一条。两条都失败时才查询兼容用的 Release API，数量降为 8 条。查询有独立时限，短暂传输 / 服务器错误最多重试一次；下载仍使用适合大文件的时限。查询全部失败会报错，不使用旧缓存伪装“已是最新版”。

提示分别标识请求受限、超时、DNS、安全连接、HTTP 服务错误或元数据无法读取，不展示原始堆栈或错误归因于私人仓库权限。用户主动取消不触发其他路径或错误提示。

`tools/update-feed.py` 从已经公开发布的稳定 Release 资产生成清单，核对官方地址、架构、体积和 GitHub 的 SHA-256，再发布仓库副本与 `update-channel` 预发布附件。该预发布仅作为固定元数据地址，不参与软件版本选择。清单拒绝回退版本；只有发布成功的包才进入清单。发布工作流自动维护，无需用户手动填入版本号。

Windows 下载继续核对字节数和 SHA-256，安卓额外核对包名、版本号与原发行签名。没有新增不明镜像、绕过 TLS 或关闭校验。

旧版已经安装在用户电脑上的更新代码不能通过服务器清单自行修复。若旧版一直无法连接 API，需关闭程序、下载 2.4.1 EXE 并替换原 EXE 后启动一次；本机数据位于独立数据目录，不要求卸载或清空。手机沿用发行密钥覆盖安装。
